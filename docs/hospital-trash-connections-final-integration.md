## IMPLEMENTATION

This is the missing source connection between **Universal Connections** and
**Hospital's Room database**. It is deliberately based on #130's existing
protected store and does NOT replace or rewrite that source-owner branch.

Before this package:
- Universal Connections had a protected issuer and native signer using
  \`/run/post-apollo/hospital/px-writer.sock\` with SOCK_SEQPACKET
  PREPARE → signed COMMIT.
- Hospital's protected database used a separate SOCK_STREAM
  \`hospital-room-writer-v1.sock\` to serve read metadata, reviewed runtime
  writes, and a different signed Trash/Restore RPC.
- Both components passed tests independently, but could not speak the same
  operation protocol.

This package adds a *second*, native, root-created SOCK_SEQPACKET endpoint
to the **same dedicated Hospital database owner**, without weakening or
replacing the existing protected metadata and legacy runtime server.

New files:
- \`bin/px_hospital_connections_consent.py\`: fixed canonical native frames
  matching Universal Connections' exact PREPARED and RECEIPT contracts.
  Root issuer SO_PEERCRED and SCM_CREDENTIALS checked per packet. Root
  policy is independent from QML and checks exact Room/action/graph/revision.
- \`bin/px-hospital-consent-writerd\`: fail-closed pre-install daemon that
  requires a systemd-provided root-owned listening FD and the existing
  protected Hospital writer's ROOT-owned config, separate database UID,
  and migrated private v12 SQLite data. It accepts no CLI options, arbitrary
  DBs, sockets, IDs, keys, unsigned actions or migration.
- \`bin/px_hospital_room_lifecycle.py\`: optional consent policy callback
  during the *same* \`BEGIN IMMEDIATE\` transaction, so revoked external
  retention permission is checked immediately before signed source mutation.
- End-to-end tests use the MERGED Universal Connections signer code at
  exact C5-H2 head \`29f816fb\`, not an invented signature protocol.
  Disposable tests prove PREPARE → signed COMMIT → Room disappears into
  Trash++ Bin → signed RESTORE → preserved Room, with revocation,
  forged/replayed actions, unchanged lineage and no Burn.

## RETENTION / LEGAL HOLD AUTHORITY

No blanket assumption of "not under legal hold" is permitted. A ROOT-managed
file, absent by default, must explicitly approve each exact Room, action,
revision and graph digest. The currently proposed v1 policy source is:

\`/etc/post-apollo/hospital/room-retention-decisions.json\`

It must be a canonical JSON object with exact fields:
\`schema = postapollo.hospital.room-retention-decisions.v1\`;
\`policyGeneration\` positive integer; \`expiresAt\` time within 24 hours;
\`decisions\` array containing records with
\`roomId\`, \`action\`, \`expectedRevision\`, \`expectedDigest\`,
\`retentionApproved\` (true only on approval), \`legalHold\` (false only when
verified). Root owns the file and ancestors; writer group may only read.
Only \`0440\`/\`0640\` file modes are allowed. Any missing, stale, duplicate,
untrusted or changed decision refuses the protected operation.

A prepared grant binds:
- **Exact Room and action**, Patient/repository and SHA-256 source graph
- Room lifecycle revision and currently clear operational dependencies
- Explicit root-controlled retention approval and no legal hold
- Unique Connections request nonce, writer process instance and expiry
- Monotonic policy generation for the current root-controlled policy file

COMMIT must match the same request and writer process, root-pinned signed
issuer grant, current protected source graph, and freshly reread retention
policy before the original Room is changed in a single SQLite transaction.
No client can submit its own policy, user-selected key or a signed grant
over the desktop read-only socket.

## WATCH OUT FOR // STILL REQUIRED BEFORE PRODUCTION

- **Root signer and writer installation** not done: needs independently
  reviewed socket-activated service units, dedicated identities, SELinux
  allowlist, fixed root executable enrollment, Polkit effective interactive
  permission rules, compositor lock/seat evidence and protected signing key.
- **Policy source needs owner acceptance.** Root-managed retention decisions
  must be produced by an authorized retention/legal-hold authority, not an
  arbitrary operator UI toggle. This package refuses if policy is missing.
  A rollback-proof monotonic policy floor and key/consent revocation procedure
  need independent security review before live activation.
- **Existing runtime writes:** PX owner must reconcile active Session,
  Assignment, Doctor and Bed branches into the same protected writer and
  ensure obsolete desktop database writers cannot access old or new Room
  data. Unknown Bed commands remain excluded from existing allowlist.
- **Schema cutover:** PX #121 v11 must merge before PX #130 v12. A
  WAL-consistent backup/recovery/rollback and source SQLite owner move must
  be verified on a disposable copy before touching any real Hospital record.
- **Application release:** Hospital UI #2069 is source-only and unmerged;
  operator final approval is separate. GIO Trash and Burn stay untouched.
  Hospital Burn is not implemented.

## 2026-11-19 // Fixed installed socket owner mismatch

Independent comparison against the **actual merged Universal Connections
issuer** found an installation-blocking mismatch: its native peer verifier
requires \`px-writer.sock\` to be owned by the policy-pinned **dedicated,
non-root Hospital database writer UID**, while the initial source
\`verify_root_socket()\` required UID 0. The protected systemd socket is
**created by root**, but its \`SocketUser\` must be the dedicated PX writer
account and the parent \`/run/post-apollo/hospital\` hierarchy must remain
root-owned and non-world-writable.

The canonical source was corrected in this same PR, not a second competing
implementation. Its CI now imports the merged Connections service itself
and proves that **both actual source-side owner checks** accept the same
reviewed socket identity, rejecting root-owned or unrelated-user sockets.
The installed systemd SocketUser/SELinux policy still requires independent
native verification and operator acceptance. This is source-level testing,
not a claim that the user's desktop service is running.
